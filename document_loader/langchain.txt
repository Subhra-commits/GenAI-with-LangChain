What is a Chain in LangChain?
A Chain is a workflow that connects multiple LangChain components together, where the output of one component becomes the input of the next component.

Think of it as a pipeline.

Input → Prompt → LLM → Parser → Output
Instead of manually calling each step, a chain executes them in sequence.

Why do we need Chains?
Without a chain:

prompt_text = prompt.invoke({"topic": "Python"})

response = model.invoke(prompt_text)

result = parser.invoke(response)

print(result)
You have to manage each step manually.

With a chain:

chain = prompt | model | parser

result = chain.invoke({"topic": "Python"})
Much cleaner and easier to maintain.

1. Simple Sequential Chain
A straightforward sequence of components.

chain = prompt | model | StrOutputParser()
Example:

from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

    input_variables=["topic"]

result = chain.invoke({"topic": "FastAPI"})

Very common in GenAI applications.

Run multiple operations simultaneously.

Different paths based on conditions.

Useful for routing tasks.

LCEL (LangChain Expression Language)
Modern LangChain chains are built using LCEL.

The | operator creates a chain.

Example:

chain = prompt | model | parser
Equivalent to:

output1 = prompt.invoke(input)

output2 = model.invoke(output1)

output3 = parser.invoke(output2)
Important Chain Methods
invoke()
For a single input.

result = chain.invoke(
    {"topic": "Python"}
)
batch()
For multiple inputs.

    {"topic": "Python"},
    {"topic": "FastAPI"},
    {"topic": "AWS"}

Processes them efficiently.

For streaming output token by token.

for chunk in chain.stream(
    {"topic": "Python"}

    print(chunk, end="")
ainvoke()
Async execution.

    {"topic": "Python"}
)
Useful in FastAPI applications.

Interview Answer
A Chain in LangChain is a sequence of components that work together to perform a task. The output of one component becomes the input to the next component. Chains help automate workflows involving prompts, LLMs, retrievers, tools, and output parsers. In modern LangChain, chains are typically built using the LangChain Expression Language (LCEL) and the | operator. Common examples include prompt-to-LLM chains, retrieval-augmented generation (RAG) chains, and structured output chains. Chains are deterministic workflows, whereas agents dynamically decide which actions or tools to use.


difference between .invoke() and format() and parser()

These three are often confusing because they operate at different stages of a LangChain pipeline.

1. format() — Creates the Prompt Text
Used with PromptTemplate.

It simply replaces placeholders with actual values and returns a string.

Example
from langchain_core.prompts import PromptTemplate

prompt = PromptTemplate(
    template="Tell me about {topic}",
    input_variables=["topic"]
)

result = prompt.format(topic="Python")

print(result)
Output:

Tell me about Python
No LLM is called here.

Purpose
Convert:

Tell me about {topic}
into:

Tell me about Python
2. invoke() — Executes a Runnable
invoke() is used on:

Prompts

Models

Parsers

Chains

It actually runs that component.

Prompt Invoke
prompt.invoke({"topic": "Python"})
Output:

StringPromptValue(text='Tell me about Python')
Notice this is not a plain string.

Model Invoke
response = model.invoke("Tell me about Python")
Output:

AIMessage(
    content="Python is a programming language..."
)
Here the LLM is called.

Chain Invoke
chain = prompt | model | StrOutputParser()

result = chain.invoke({"topic": "Python"})
Output:

Python is a programming language...
The entire pipeline executes.

3. parser.parse() — Converts Output to Desired Format
Parsers take the model output and transform it.

Example
from langchain_core.output_parsers import JsonOutputParser

parser = JsonOutputParser()

text = '''
{
  "name": "John",
  "age": 30
}
'''

result = parser.parse(text)

print(result)
Output:

{
  'name': 'John',
  'age': 30
}
No LLM call happens here.

It's just data conversion.

End-to-End Example
Step 1: Format Prompt
prompt_text = prompt.format(topic="Python")
Output:

Tell me about Python
Step 2: Call LLM
response = model.invoke(prompt_text)
Output:

AIMessage(
    content="Python is a programming language..."
)
Step 3: Parse Output
result = parser.parse(response.content)
Output:

{
   ...
}
Relationship in a Chain
When you write:

chain = prompt | model | parser
and then:

chain.invoke({"topic": "Python"})
internally LangChain does something similar to:

prompt_value = prompt.invoke({"topic": "Python"})

llm_response = model.invoke(prompt_value)

final_result = parser.invoke(llm_response)
You only call .invoke() once, and LangChain handles the rest.

Quick Comparison
Method	Used On	Purpose	Calls LLM?
format()	PromptTemplate	Replace variables and generate prompt text	❌
invoke()	Prompt, Model, Parser, Chain	Execute the component	Depends on component
parse()	Output Parser	Convert text into structured output	❌
Interview Answer
format() is used with prompt templates to substitute variables and generate the final prompt string without executing anything. invoke() is used to execute a LangChain runnable such as a prompt, model, parser, or entire chain. parse() is used by output parsers to transform the model's textual response into a structured format such as a dictionary or Pydantic object. In a typical workflow, the prompt is formatted, the model is invoked, and the response is parsed.


branching chain

What is a Branching Chain in LangChain?
A Branching Chain is a workflow where the execution path changes based on a condition.

Instead of a fixed flow:

Input → Prompt → LLM → Output
you have multiple possible paths:

                Input
                  │
                  ▼
             Condition
              /     \
             /       \
            ▼         ▼
      Chain A      Chain B
The chain decides which branch to execute based on the input.

Why do we need Branching?
Imagine a customer support chatbot:

User Query
    │
    ▼
Check Query Type
    │
 ┌──┴─────────┐
 ▼            ▼
Technical   Billing
Chain       Chain
Different prompts and workflows are used for different types of questions.

Using RunnableBranch
LangChain provides RunnableBranch for this purpose.

Example
from langchain_core.runnables import RunnableBranch
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

positive_prompt = PromptTemplate.from_template(
    "Write a thank you message for this positive review: {review}"
)

negative_prompt = PromptTemplate.from_template(
    "Write an apology message for this negative review: {review}"
)

branch = RunnableBranch(
    (
        lambda x: "good" in x["review"].lower(),
        positive_prompt | model | StrOutputParser()
    ),
    negative_prompt | model | StrOutputParser()
)
Invoke:

result = branch.invoke(
    {"review": "This product is good"}
)
The positive branch executes.

Review

   ▼

   │
 ┌─┴───────────┐
 ▼             ▼
Positive    Negative
Prompt       Prompt
For:

"The service was excellent."
Use a gratitude response.

For:

"The service was terrible."
Use an apology response.

  ▼

The first matching condition wins.

A Branching Chain in LangChain is a workflow that routes execution to different chains based on conditions. Unlike a sequential chain that always follows the same path, a branching chain evaluates input and chooses the appropriate branch. LangChain provides RunnableBranch to implement this behavior. what Runnable lambda doing

In the RunnableBranch example, the lambda function is the condition checker. It decides which branch should run.

Example:

branch = RunnableBranch(
    (
        lambda x: "good" in x["review"].lower(),
        positive_chain
    ),
    negative_chain
)
Let's break it down.

Input
{
    "review": "This product is good"
}
LangChain passes this input to the lambda:

x = {
    "review": "This product is good"
}
The lambda evaluates:

"good" in x["review"].lower()
which becomes:

"good" in "this product is good"
Result:

True
Since the condition is True, LangChain executes:

positive_chain
If the review is negative
Input:

{
    "review": "This product is terrible"
}
Lambda:

"good" in "this product is terrible"
Result:

False
So LangChain skips that branch and executes the default branch:

negative_chain
Why use a lambda?
A lambda is just a short anonymous function.

Instead of:

def is_positive(x):
    return "good" in x["review"].lower()
you can write:

lambda x: "good" in x["review"].lower()
Both are equivalent.

More realistic example
Suppose you're routing interview questions.

branch = RunnableBranch(
    (
        lambda x: "python" in x["question"].lower(),
        python_chain
    ),
    (
        lambda x: "sql" in x["question"].lower(),
        sql_chain
    ),
    (
        lambda x: "aws" in x["question"].lower(),
        aws_chain
    ),
    general_chain
)
Input:

{
    "question": "Explain joins in SQL"
}
Checks:

"python" in question   # False
"sql" in question      # True
So:

sql_chain
runs.

In LangChain, anything that can be executed is called a Runnable.

    lambda x: len(x)

Output:

Here the lambda itself becomes a runnable component that can be placed inside a chain.

    prompt

Flow:

Interview Answer
In RunnableBranch, the lambda function acts as a condition evaluator. It receives the input data and returns either True or False. Based on the result, LangChain decides which branch of the workflow to execute. The lambda is similar to an if condition in Python and is commonly used for routing inputs to different chains. RunnableLambda can also be used to wrap custom Python functions so they can participate as steps in a LangChain pipeline.


What is runnables? Why to use it? What are the common functions in runnables?

This is a very common LangChain interview topic.

What are Runnables in LangChain?
A Runnable is the fundamental building block in modern LangChain.

A Runnable is anything that can take an input, perform some operation, and produce an output.

Examples:

PromptTemplate
ChatOpenAI
ChatHuggingFace
StrOutputParser
JsonOutputParser
RunnableLambda
RunnableBranch
Retriever
Entire Chain
All of these are Runnables because they support a common interface.

Why were Runnables introduced?
Before LCEL (LangChain Expression Language), chains were built using classes like:

LLMChain
SequentialChain
SimpleSequentialChain
These became difficult to compose and maintain.

Runnables provide:

Standardized interface

Easy chaining using |

Streaming support

Async support

Batch processing

Parallel execution

Branching workflows

Think of Runnables as Lego Blocks
Every component:

Prompt
Model
Parser
Retriever
Custom Function
is a Runnable.

You can connect them together:

chain = prompt | model | parser
because all of them understand the same Runnable interface.

Common Runnable Methods
1. invoke()
Executes on a single input.

result = chain.invoke(
    {"topic": "Python"}
)
Input:

{"topic": "Python"}
Output:

"Python is a programming language..."
Most commonly used method

Executes multiple inputs at once.

results = chain.batch([

[

    "...AWS...",

for chunk in chain.stream(

In LangChain, a Runnable is the core abstraction that represents any component capable of accepting input and producing output.
